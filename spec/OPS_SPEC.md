# 공통 운영 파일 규격 (OPS_SPEC) · 판 1

서버 없이 여러 게임의 **우편 (중심) · 점검 · 강제 업데이트** 를 운영하는 규격이다.
공지 · 이벤트 소개 · 재화 보상은 모두 **우편**으로 보낸다 (2026-10-20 대표 결정 — 공지를 따로 화면에 띄우지 않는다 · 콘솔은 `notices` 를 늘 빈 배열로 쓴다 · 옛 앱 호환으로 칸은 남김).
운영자는 PC 의 콘솔 (`console/ops_console.html`) 로 게임마다 파일 한 장을 만들어 **서명**하고, 이 공개 저장소에 올린다.
게임 앱은 그 파일을 내려받아 **서명을 확인한 뒤에만** 반영한다.

```
[운영자 PC: ops_console.html] ─ 작성 · 서명 ─▶ repo/games/<게임>/ops.json + ops.json.sig ─ 올리기 (git push) ─▶ GitHub (공개)
                                                                                                        │
[게임 앱] ◀── raw.githubusercontent.com/B-SGL/commonmanagement/main/games/<게임>/ops.json (+ .sig) ──────┘
```

## 1. 폴더 (운영자 PC · `C:\Users\lsg50\Desktop\common management`)

| 자리 | 무엇 | 공개 |
|---|---|---|
| `README.md` | 쓰는 법 | 아니오 (PC 에만) |
| `올리기.bat` | `repo` 의 바뀐 운영 파일을 커밋 · 올리기 | 아니오 |
| `keys/<게임>.private.jwk` | **비밀 열쇠** — 서명에만 · 절대 저장소에 넣지 않는다 · 따로 백업 | **절대 아니오** |
| `keys/<게임>.public.jwk` | 공개 열쇠 (게임 코드에 넣는 값) | 넣어도 무방 (앱에 들어간다) |
| `repo/` | 저장소 `B-SGL/commonmanagement` 받은 자리 | 예 |
| `repo/console/ops_console.html` | 콘솔 | 예 (비밀 없음) |
| `repo/spec/OPS_SPEC.md` | 이 문서 | 예 |
| `repo/games/<게임>/ops.json` · `ops.json.sig` | 게임마다 운영 파일 · 서명 | 예 |

이 기능을 안 쓰려면 `common management` 폴더를 지우면 된다 (게임은 마지막으로 올린 파일 · 또는 파일 없음으로 그대로 돈다).

## 2. 서명

- 방식: **RSASSA-PKCS1-v1_5 · SHA-256 · RSA 2048** (게임마다 열쇠 한 쌍).
  - 브라우저 WebCrypto 로 서명하고 Unity (Mono · IL2CPP) 의 `RSACryptoServiceProvider` 로 확인할 수 있는 조합 (Ed25519 는 Unity 에 기본으로 없다).
- 서명 대상: `ops.json` 파일의 **바이트 그대로** (UTF-8 · BOM 없음 · 줄바꿈 LF).
- `ops.json.sig`: 서명 바이트의 **Base64** (한 줄 · ASCII).
- 공개 열쇠는 JWK (`n` · `e` · Base64URL) — 게임 코드에는 `n` · `e` 두 값을 상수로 넣는다.
- 앱은 서명이 맞지 않으면 그 파일을 **통째로 버린다** (한 글자라도 다르면).

## 3. `ops.json` (판 1)

```json
{
  "format": 1,
  "game": "jumsoi",
  "seq": 3,
  "issued_at": "2026-10-19T12:00:00Z",
  "min_version": "0.93",
  "latest_version": "0.96",
  "store_url": "https://play.google.com/store/apps/details?id=…",
  "maintenance": { "on": false, "block": false, "start": "", "end": "",
                   "title": { "ko": "점검 안내", "en": "Maintenance" },
                   "body":  { "ko": "…", "en": "…" } },
  "notices": [
    { "id": "n20261019a", "repeat": "daily", "start": "2026-10-19T00:00:00Z", "end": "2026-10-26T00:00:00Z",
      "title": { "ko": "…", "en": "…" }, "body": { "ko": "…", "en": "…" } }
  ],
  "mails": [
    { "id": "m20261019a", "start": "2026-10-19T00:00:00Z", "end": "2026-10-26T00:00:00Z",
      "to": [], "min_stage": 0, "min_version": "",
      "title": { "ko": "추석 선물", "en": "Harvest gift" }, "body": { "ko": "…", "en": "…" },
      "rewards": [ { "type": "dia", "amount": 500 } ] }
  ]
}
```

| 칸 | 뜻 |
|---|---|
| `format` | 규격 판 (지금 1) · 앱이 모르는 더 높은 판은 쓰지 않는다 |
| `game` | 게임 이름 (앱은 제 이름과 다르면 버린다) |
| `seq` | 올릴 때마다 1씩 오르는 번호 — 앱은 **가진 것보다 낮은 번호는 무시** (옛 파일 되돌리기 · 다시 보내기 막음) |
| `issued_at` | 만든 시각 (UTC · ISO 8601) |
| `min_version` | 이보다 낮은 판은 **강제 업데이트** 화면 (비우면 없음) |
| `latest_version` | 이보다 낮으면 「새 판이 있어요」 안내 (막지 않음 · 비우면 없음) |
| `store_url` | 업데이트 단추가 여는 주소 |
| `maintenance` | 점검 안내 — `on` 이 참이고 기간 안이면 켤 때 안내 · `block` 이 참이면 그 동안 게임을 막는다 (서버 없는 게임은 보통 거짓) |
| `notices[]` | (쓰지 않음 · 늘 `[]`) 옛 공지 칸 — 앱은 읽을 수 있지만 콘솔이 만들지 않는다 |
| `mails[]` | 우편 — `to` 가 비면 모두 · 아니면 그 플레이어 번호만 · `min_stage` · `min_version` 조건 · `rewards[]` (비면 글만 있는 우편 — 읽고 「확인」 하면 사라진다) · 파일 차례 = 우편함 차례 (콘솔은 새 우편을 맨 앞에) |

- 글은 `{ "ko": …, "en": … }` — 앱 언어가 없으면 `ko` (첫 언어).
- 시각은 모두 UTC ISO 8601 (`…Z`) · 빈 글이면 「제한 없음」.
- `id` 는 `[A-Za-z0-9_-]` 1 ~ 32자 · 게임 안에서 한 번 쓴 번호는 다시 쓰지 않는다 (앱이 받은 번호를 기억한다).
- 보상 `type` 은 게임마다 정한다 (점소이: `dia` = 금원보 · 한도 100,000 / `gold_h` = 엽전 N시간치 — 받는 사람의 상점 초당 엽전 × N시간 · 한도 240). 앱이 모르는 종류는 건너뛴다.
  - 새 종류를 더하려면 게임 코드 (판정 · 지급) 를 먼저 고치고, 그 판이 퍼진 뒤 콘솔 `GAMES` 에 더한다.

## 4. 앱이 지킬 것

1. **받기** — 켤 때 · 앱으로 돌아올 때 (10분 간격 이상) `ops.json` · `ops.json.sig` 를 받는다. 짧은 시간 제한 · 실패해도 게임은 그대로.
2. **확인** — 서명 · `format` · `game` · `seq` (가진 것 이상) 를 본다. 통과한 파일만 기기에 보관한다.
3. **시각** — 기간 판단은 기기 시계가 아니라 **받은 응답의 `Date` 머리** (+ 받은 뒤 흐른 단조 시간). 한 번도 못 받았으면 보관본의 `issued_at` 이후로만 · 그것도 없으면 운영 기능은 쉰다.
4. **오프라인** — 마지막 확인본을 쓴다 · 처음부터 없으면 운영 기능은 조용히 꺼진다.
5. **우편** — 기간 안 · 조건 맞음 · 아직 안 받음만 보인다 · 받으면 **받은 번호를 저장에 적고** 한 번만 준다 (번호는 저장에 오래 남긴다).
6. **플레이어 번호** — 처음 켤 때 무작위로 만들어 저장에 둔다 (`P` + 10자 · 헷갈리는 글자 0 O 1 I L 없음) · 설정에 보이고 복사할 수 있다 · 기기 ID · 광고 ID 는 쓰지 않는다.
7. **보내는 것 없음** — 앱은 공개 파일을 받기만 한다 (개인정보처리방침에 「공지 파일을 내려받는다」 를 적는다).

## 5. 한계 (알고 쓰기)

- 누가 받았는지 운영자가 볼 수 없다 (받은 기록은 각자의 기기에만).
- 앱을 지우고 다시 깔면 기간 안의 우편을 또 받을 수 있다 (기간을 짧게 · 보상을 적게 · 나중에 클라우드 저장).
- 기기 저장을 손으로 고치는 사람은 막지 못한다 (서버 없는 게임의 모든 보상과 같다).
- `raw.githubusercontent.com` 은 몇 분 캐시가 있다 — 올린 뒤 바로 보이지 않을 수 있다.
