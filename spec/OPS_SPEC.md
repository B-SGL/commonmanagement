# 공통 우편 운영 규격 (OPS_SPEC) · 판 1

서버 없이 여러 게임에 **우편** (공지 · 이벤트 소개 · 재화 보상) 과 **점검 · 강제 업데이트** 를 내보내는 규격이다.
공지를 따로 화면에 띄우지 않는다 — 안내는 모두 우편으로 (2026-10-20 대표 결정).

```
[운영자 PC]  운영콘솔 열기.bat → 운영콘솔.html (게임 고르기 · 우편 쓰기)
                └ 「저장하고 보내기」 → 서명 → repo/games/<게임>/ops.json + ops.json.sig → git push → GitHub (공개 저장소)
[게임 앱]    raw.githubusercontent.com/B-SGL/commonmanagement/main/games/<게임>/ops.json (+ .sig) 를 받아 서명 확인 → 우편함
```

## 2. 서명

- 방식: **RSASSA-PKCS1-v1_5 · SHA-256 · RSA 2048** (게임마다 열쇠 한 쌍 · 콘솔 「게임 설정 › 서명 열쇠 › 열쇠 만들기」).
  - 브라우저 WebCrypto 로 서명하고 Unity (Mono · IL2CPP) 의 `RSACryptoServiceProvider` 로 확인할 수 있는 조합 (Ed25519 는 Unity 에 기본으로 없다).
- 서명 대상: `ops.json` 파일의 **바이트 그대로** (UTF-8 · BOM 없음 · 줄바꿈 LF). 저장소의 `.gitattributes` 가 `games/**` 의 줄바꿈 변환을 막는다.
- `ops.json.sig`: 서명 바이트의 **Base64** (한 줄 · ASCII).
- 공개 열쇠는 JWK (`n` · `e` · Base64URL) — 게임 코드에는 `n` · `e` 두 값을 상수로 넣는다.
- 앱은 서명이 맞지 않으면 그 파일을 **통째로 버린다** (한 글자라도 다르면).

## 3. `ops.json` (판 1)

```json
{
  "format": 1,
  "game": "jumsoi",
  "seq": 3,
  "issued_at": "2026-10-19T12:00:00Z",
  "min_version": "0.93",
  "latest_version": "0.96",
  "store_url": "https://play.google.com/store/apps/details?id=…",
  "maintenance": { "on": false, "block": false, "start": "", "end": "",
                   "title": { "ko": "점검 안내", "en": "Maintenance" },
                   "body":  { "ko": "…", "en": "…" } },
  "notices": [],
  "mails": [
    { "id": "m202610191200ab1", "start": "2026-10-19T00:00:00Z", "end": "2026-10-26T00:00:00Z",
      "to": [], "min_stage": 0, "min_version": "",
      "title": { "ko": "추석 선물", "en": "Harvest gift" }, "body": { "ko": "…", "en": "…" },
      "rewards": [ { "type": "dia", "amount": 500 } ] }
  ]
}
```

| 칸 | 뜻 |
|---|---|
| `format` | 규격 판 (지금 1) · 앱이 모르는 더 높은 판은 쓰지 않는다 |
| `game` | 게임 이름 = 게임 파일의 `id` (앱은 제 이름과 다르면 버린다) |
| `seq` | 보낼 때마다 1씩 오르는 번호 — 앱은 **가진 것보다 낮은 번호는 무시** (옛 파일 되돌리기 막음) |
| `issued_at` | 만든 시각 (UTC · ISO 8601) |
| `min_version` | 이보다 낮은 판은 **강제 업데이트** 화면 (비우면 없음) |
| `latest_version` | 이보다 낮으면 「새 버전이 있어요」 안내 (막지 않음 · 비우면 없음) |
| `store_url` | 업데이트 단추가 여는 주소 |
| `maintenance` | 점검 안내 — `on` 이 참이고 기간 안이면 켤 때 안내 · `block` 이 참이면 그 동안 게임을 막는다 (서버 없는 게임은 보통 거짓) |
| `notices[]` | 늘 `[]` (옛 공지 칸 · 콘솔이 만들지 않는다 · 앱은 무시해도 된다) |
| `mails[]` | 우편 — `to` 가 비면 모두 · 아니면 그 플레이어 번호만 · `min_stage` · `min_version` 조건 · `rewards[]` (비면 글만 있는 우편) · 파일 차례 = 우편함 차례 (콘솔은 새 우편을 맨 앞에) |

- 글은 `{ "ko": …, "en": … }` — 앱 언어 글이 비면 `ko`.
- 시각은 모두 UTC ISO 8601 (`…Z`) · 빈 글이면 「제한 없음」.
- `id` 는 `[A-Za-z0-9_-]` 1 ~ 32자 · 콘솔이 `m` + 시각 + 난수로 만든다 · 한 번 쓴 번호는 다시 쓰지 않는다 (앱이 받은 번호를 기억한다).
  - `sys_` 로 시작하는 번호는 게임 앱이 스스로 만드는 우편 자리 (운영 파일에 쓰지 않는다 · 앱은 운영 파일의 `sys_` 번호를 무시한다).
- 보상 `type` 은 게임마다 정한다 (게임 파일의 `rewards` = 앱이 아는 종류). 앱이 모르는 종류는 건너뛴다.
  - 새 종류는 **게임 코드를 먼저** 고치고, 그 판이 퍼진 뒤 게임 파일에 더한다.

## 4. 앱이 지킬 것

1. **받기** — 켤 때 · 앱으로 돌아올 때 (10분 간격 이상) · **켜 둔 동안 5분마다** `ops.json` · `ops.json.sig` 를 받는다. 짧은 시간 제한 (8초) · 실패해도 게임은 그대로.
2. **확인** — 서명 · `format` · `game` · `seq` (가진 것 이상) 를 본다. 통과한 파일만 기기에 보관한다.
3. **시각** — 기간 판단은 기기 시계가 아니라 **받은 응답의 `Date` 머리** (+ 받은 뒤 흐른 단조 시간). 못 받았으면 마지막으로 안 서버 시각보다 앞으로 가지 않는다.
4. **오프라인** — 마지막 확인본을 쓴다 · 처음부터 없으면 운영 기능은 조용히 꺼진다.
5. **우편** — 기간 안 · 조건 맞음 · 아직 안 받음만 「받기」 · 받으면 **받은 번호를 저장에 적고** 한 번만 준다 (번호는 저장에 오래 남긴다 · 초기화해도 남긴다).
   - 받은 우편은 기간 안이면 「받음」 으로 남기고 지울 수 있게 (모두 삭제는 받은 것만 — 안 받은 보상은 지우지 않는다).
6. **플레이어 번호** — 처음 켤 때 무작위로 만들어 저장에 둔다 (`P` + 10자 · 헷갈리는 글자 0 O 1 I L 없음 · 글자 `23456789ABCDEFGHJKMNPQRSTUVWXYZ`) · 우편함 · 설정에 보인다 · 기기 ID · 광고 ID 는 쓰지 않는다.
7. **보내는 것 없음** — 앱은 공개 파일을 받기만 한다 (개인정보처리방침에 「운영 파일을 내려받는다 · 인터넷 권한」 을 적는다).

## 5. 한계 (알고 쓰기)

- 누가 받았는지 운영자가 볼 수 없다 (받은 기록은 각자의 기기에만).
- 앱을 지우고 다시 깔면 기간 안의 우편을 또 받을 수 있다 (기간을 짧게 · 보상을 적게 · 나중에 클라우드 저장).
- 기기 저장을 손으로 고치는 사람은 막지 못한다 (서버 없는 게임의 모든 보상과 같다).
- `raw.githubusercontent.com` 은 약 5분 캐시가 있다 — 보낸 뒤 켜 둔 앱에 닿기까지 최대 10분쯤.

## 7. 새 게임 붙이기 (게임 개발 방이 할 일)

1. `slots/` 에 **내 게임 파일 하나만** 만들거나 고친다 (`<번호>_<id>.js` · `OPS_GAME({…})`) — `slot` · `id` (영문 소문자 · 숫자 · `_` · 처음 보낸 뒤에는 바꾸지 않는다) · `rewards` (그 앱이 아는 보상 종류 · 한도는 앱의 윗한도와 같게) · `note` · **`ready: true`** (콘솔 사이드바의 「준비 중」 이 운영 화면으로 바뀐다). 게임마다 파일이 따로라 여러 방이 동시에 작업해도 겹치지 않는다.
2. 운영자 (대표) 가 콘솔 사이드바에서 그 게임을 골라 「게임 설정 › 서명 열쇠 › 열쇠 만들기」 → `keys/<id>.public.jwk` 가 생긴다. (게임 방이 열쇠를 만들지 않는다 — 비밀 열쇠는 운영자 PC 에만.)
3. 게임 코드에 넣는다: 받는 주소 `https://raw.githubusercontent.com/B-SGL/commonmanagement/main/games/<id>/` · 공개 열쇠 `n` · `e` (`keys/<id>.public.jwk`) · `game` 값 `<id>`.
4. 앱이 §4 를 지킨다 — 받기 · 서명 확인 · 보관 · 서버 시각 · 우편함 (받기 · 모두 받기 · 받음 · 삭제 · 모두 삭제) · 플레이어 번호 · 인터넷 권한 · 개인정보 문안.
5. 시험: 콘솔에서 그 게임에 짧은 기간 (1일) · 작은 보상의 시험 우편을 보내고 앱에서 받아 본다.
